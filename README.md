رِواق الجامعي — اقرأ هذا الملف أولاً
====================================

هذا الدليل للمبتدئ. اتبع الخطوات بالترتيب ولا تتخطَّ أي خطوة.

مهم جداً قبل البداية:
- إذا شغّلت schema.sql بنجاح في مشروع Supabase نفسه سابقاً (وظهرت Success. No rows returned)، فهذا يعني أن الاستعلام نجح. لا تشغّل schema.sql مرة ثانية على المشروع نفسه.
- إذا أنشأت مشروع Supabase جديداً تماماً ولم تشغّل عليه أي SQL، اتبع خطوة قاعدة البيانات أدناه.
- لا ترسل كلمة مرور قاعدة البيانات أو أي مفتاح سري لأحد، ولا تضع service_role key في ملفات الموقع.

الجزء 1: فك الضغط وفتح الملفات
1. نزّل ملف riwaq-university-notes-portal-v4.zip.
2. افتح مجلد Downloads في حاسوبك.
3. اضغط بالزر الأيمن على ملف ZIP واختر Extract All / استخراج الكل.
4. افتح المجلد الناتج، ثم افتح المجلد الذي اسمه university-notes-portal.
5. افتح VS Code.
6. من القائمة File اختر Open Folder.
7. اختر مجلد university-notes-portal الذي استخرجته، ثم اضغط Select Folder.
8. في الجانب الأيسر يجب أن ترى ملفات مثل index.html و config.js و schema.sql و app.js.

الجزء 2: إنشاء مشروع Supabase (قاعدة بيانات الموقع)
1. افتح https://supabase.com في المتصفح وسجّل الدخول.
2. أنشئ مشروعاً جديداً بالضغط على New project.
3. اختر المؤسسة إن طُلب ذلك، واكتب اسم المشروع: riwaq-university.
4. ضع كلمة مرور قوية لقاعدة البيانات واحفظها في مكان آمن. هذه ليست كلمة مرور الطالب ولا تكتبها في config.js.
5. اختر المنطقة الأقرب المتاحة، ثم اضغط Create new project.
6. انتظر حتى يصبح المشروع جاهزاً.

الجزء 3: إنشاء جداول قاعدة البيانات — للمشروع الجديد فقط
إذا لم تنفذ schema.sql في هذا المشروع الجديد:
1. في لوحة Supabase، افتح SQL Editor من الشريط الجانبي.
2. اضغط + أو New query لفتح استعلام جديد.
3. ارجع إلى VS Code وافتح schema.sql.
4. اضغط Ctrl+A لتحديد الملف كله، ثم Ctrl+C للنسخ.
5. ارجع إلى Supabase SQL Editor واضغط داخل مساحة الكتابة، ثم Ctrl+V للصق.
6. اضغط Run.
7. إذا ظهرت Success. No rows returned فهذا طبيعي لأوامر إنشاء الجداول.
8. إذا ظهر خطأ أحمر، توقف وصوّر الخطأ. لا تشغّل الملف مرات متكررة ولا تخمّن الحل.

إذا كنت قد شغّلت schema.sql بنجاح في المشروع نفسه من قبل، تخطَّ الجزء 3. لا تستخدم upgrade_v3.sql إلا إذا كنا نحدّث قاعدة قديمة وبناءً على توجيه محدد.

الجزء 4: ربط ملفات الموقع بقاعدة البيانات
1. في Supabase افتح Project Settings ثم API، أو اضغط Connect وابحث عن بيانات API.
2. انسخ Project URL. يكون شكله شبيهاً بـ https://xxxx.supabase.co.
3. انسخ المفتاح العام فقط: anon/public أو publishable.
4. لا تنسخ service_role أو secret key.
5. ارجع إلى VS Code وافتح config.js.
6. ستجد قيماً فارغة أو أمثلة. استبدلها هكذا، مع وضع قيمك الحقيقية بين علامتي الاقتباس:

window.PORTAL_CONFIG = {
  SUPABASE_URL: "ضع Project URL هنا",
  SUPABASE_ANON_KEY: "ضع المفتاح العام هنا",
  ADMIN_EMAIL: "ضع بريدك الإلكتروني هنا",
  SITE_TITLE: "رِواق الجامعي"
};

7. احفظ الملف بالضغط على Ctrl+S.
8. لا تضع كلمة مرور حسابك في config.js.

الجزء 5: تشغيل الموقع على الحاسوب
الطريقة الأسهل باستخدام VS Code:
1. في VS Code اضغط أيقونة Extensions على الجانب الأيسر.
2. ابحث عن Live Server.
3. ثبّت إضافة Live Server إذا لم تكن مثبتة.
4. افتح index.html.
5. اضغط بالزر الأيمن داخل الملف واختر Open with Live Server.
6. يفتح الموقع في المتصفح. لا تفتح index.html بالنقر المزدوج من File Explorer.
7. إذا ظهر الموقع لكن المواد غير ظاهرة، هذا متوقع إذا لم تضف مواداً بعد أو إذا لم تتصل قاعدة البيانات. افحص config.js أولاً.

الجزء 6: إنشاء حساب المسؤول
1. من الموقع اضغط تسجيل الدخول ثم اختر إنشاء حساب.
2. أدخل الاسم والبريد الإلكتروني وكلمة المرور.
3. يجب أن يكون البريد نفسه الذي كتبته في ADMIN_EMAIL داخل config.js.
4. إذا وصلت رسالة تأكيد من Supabase، افتحها واضغط رابط التأكيد.
5. ارجع إلى Supabase وافتح SQL Editor ثم اضغط + لعمل استعلام جديد.
6. الصق الأمر التالي بعد استبدال البريد ببريد حسابك نفسه:

update public.profiles
set role = 'admin'
where lower(email) = lower('you@example.com');

7. اضغط Run. استبدل you@example.com ببريدك الحقيقي قبل التشغيل.
8. إذا ظهرت 1 row affected أو ما يشبهها فهذا جيد. إذا ظهرت 0 rows، فغالباً الحساب لم يُنشأ أو البريد مختلف؛ لا تتابع قبل التحقق.
9. ارجع إلى الموقع، سجّل الخروج، ثم سجّل الدخول ببريدك وكلمة المرور.
10. ينبغي أن يفتح رابط لوحة الإدارة لحساب المسؤول. حسابات الطلاب العادية لا تحصل على صلاحية الإدارة.

الجزء 7: تجربة تسجيل الطالب
1. افتح نافذة خاصة في المتصفح أو استخدم بريداً آخر.
2. اضغط إنشاء حساب.
3. اكتب الاسم والبريد الإلكتروني وكلمة المرور.
4. بعد إنشاء الحساب، جرّب تسجيل الخروج.
5. جرّب تسجيل الدخول باستخدام البريد الإلكتروني وكلمة المرور فقط. لا يُطلب الاسم في شاشة تسجيل الدخول.
6. لا تستخدم حساب الطالب لاختبار صلاحيات المسؤول.

الجزء 8: رفع الموقع إلى GitHub Pages (بعد نجاح الاختبار المحلي)
1. افتح https://github.com وسجّل الدخول.
2. اضغط New repository وأنشئ مستودعاً جديداً باسم riwaq-university.
3. افتح المستودع واضغط Add file ثم Upload files.
4. ارفع محتويات مجلد university-notes-portal نفسها (مثل index.html و styles.css و app.js و admin.html و admin.js و config.js و schema.sql)، وليس ملف ZIP وحده.
5. اضغط Commit changes.
6. من المستودع افتح Settings ثم Pages.
7. اختر Deploy from a branch، والفرع main، والمجلد /(root)، ثم Save.
8. انتظر حتى يعطيك GitHub رابطاً للموقع.
9. في Supabase افتح Authentication ثم URL Configuration.
10. ضع رابط الموقع المنشور في Site URL وأضفه أيضاً إلى Redirect URLs. أضف رابط Live Server المحلي الذي ظهر عند تشغيله أيضاً.

أخطاء شائعة
- الاسم يظهر عند تسجيل الدخول: تأكد أنك استخرجت الإصدار الرابع كاملاً ولم تخلط ملفات من نسخ مختلفة. حقل الاسم مطلوب في إنشاء الحساب فقط.
- تسجيل الدخول لا يعمل: استخدم البريد الذي أنشأت الحساب به، وتأكد من كلمة المرور وتأكيد البريد إذا كان مفعلاً.
- الاتصال لا يعمل: راجع URL والمفتاح العام في config.js.
- لوحة الإدارة لا تفتح: تحقق أن بريد ADMIN_EMAIL مطابق وأن role في public.profiles يساوي admin.
- لم تظهر أسماء الطلاب: سجّل الدخول بحساب مسؤول فعلياً، وتأكد أن الجداول والسياسات نُفذت بنجاح.
- لا تشارك كلمة مرور قاعدة البيانات أو service_role key. المفتاح الموجود في الموقع يجب أن يكون المفتاح العام فقط.

إذا توقفت عند أي خطوة، أرسل صورة للشاشة واذكر رقم الجزء ورقم الخطوة. لا ترسل كلمات مرور أو مفاتيح API في الصورة.

## تحديث الإصدار الخامس (مهم للموقع الحالي)

إذا كان موقعك يعمل بالفعل بالإصدار الرابع، لا تعِد إنشاء المشروع ولا تحذف الجداول. نفّذ الخطوات التالية:

1. خذ نسخة احتياطية من ملفات الموقع الحالية.
2. من Supabase افتح **SQL Editor** ثم أنشئ استعلامًا جديدًا.
3. افتح ملف `upgrade_v5.sql` الموجود مع ملفات الإصدار الخامس، وانسخ محتواه كاملًا إلى SQL Editor ثم اضغط **Run** مرة واحدة.
4. إذا ظهرت `Success. No rows returned` فهذا طبيعي مع أوامر إنشاء الجداول والسياسات. إذا ظهر خطأ أحمر، توقف وصوّر الخطأ بدل تشغيل الاستعلام مرارًا.
5. انشر ملفات الإصدار الخامس الجديدة في مستودع GitHub Pages نفسه، مع الإبقاء على إعدادات `config.js` الخاصة بمشروع Supabase.
6. افتح `admin.html` وسجّل الدخول، ثم افتح «المراحل والكورسات» لإدارة الكورسات، و«المظهر والتواصل» لتحديد رابط تيليجرام وبريد التواصل.
7. اختبر الموقع العام في نافذة خاصة أو متصفح آخر: يجب أن تظهر الكورسات المنشورة ووسائل التواصل التي ضبطتها.

**لا تشارك مفتاح `service_role` ولا كلمة مرور حساب المسؤول.** الموقع يستخدم المفتاح العام `anon`/`publishable` مع سياسات RLS في Supabase.

### إذا ظهر `email rate limit exceeded`

هذه الرسالة غالبًا من خدمة رسائل المصادقة في Supabase، وليست من جدول المستخدمين. افتح إعدادات Authentication والبريد الإلكتروني في مشروع Supabase، راجع حدود إرسال رسائل التأكيد، واضبط SMTP مخصصًا عند الإطلاق العام. لا تحتاج إلى حذف قاعدة البيانات. لا تعطل تأكيد البريد على موقع عام إلا إذا كنت تقبل أن البريد قد لا يكون متحققًا منه.
